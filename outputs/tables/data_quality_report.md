### 2b. Score / period availability -- CORRECTION TO A STANDING PROJECT ASSUMPTION

`live_lines.csv` carries no score, clock or period. But `live_snapshots.csv` (**1,269 rows, 27 game_ids**)
carries `period, clock, away_score, home_score, h_fouls, a_fouls, h_to, a_to, h_reb, a_reb, last_play`,
was written by the **same poller** (identical `ts` strings, identical start and end instants), and covers
**all 27 of the 27 in-play-odds games**.

- 98.3% of in-play odds rows have a state snapshot within 90s; median |dt| to nearest snapshot = **0s**.
- So live game state IS joinable. The standing 'game state is not reconstructable' note is wrong on
  mechanism. It is right in spirit, because the snapshot trace is shallow and truncated:
  - snapshots per game: median 52 (min 2, max 104)
  - only **11 of 27 games are captured into Q4**; 21 contain a Q1 row; **0 games have a complete
    tip-to-final state trace**. The poller starts and stops mid-game.
  - so any live-state study is on 27 games with partial windows, not 27 full games.
- `elo_model/plays_full.csv` holds 1,058 games of period + running score, but the game_id intersection
  with the 27 live-odds games is **exactly 0** (2019-2023 era vs 2026). It cannot fill the gap.
